# Googleドライブによる自動同期の初回設定

アプリの「設定 → Googleドライブで自動同期」から利用します。コードの実装だけでは接続は有効になりません。ご自身のGoogle Cloudプロジェクトで以下の設定が必要です。クライアントシークレット、サービスアカウント、決済情報をこのアプリに設定する必要はありません。

## 管理者が一度だけ行う設定

1. [Google Cloud Console](https://console.cloud.google.com/)で、このアプリ用のプロジェクトを作成・選択します。
2. 「APIとサービス → ライブラリ」から **Google Drive API** を有効にします。
3. 「Google Auth Platform」でアプリ名、連絡先、Audienceを設定します。個人のGoogleアカウントで使う場合はExternalです。Testingで運用する間は、使用するGoogleアカウントをTest usersに追加します。
4. Data Accessに `https://www.googleapis.com/auth/drive.appdata` だけを登録します。このアプリは通常のドライブに対するdrive・drive.file等のスコープを要求しません。
5. Clientsで **Web application** のOAuthクライアントIDを作成します。Authorized JavaScript originsに `https://uchionsummer-alt.github.io` を追加します。パス `/for_FP3/` は付けません。今回のポップアップのtoken modelはリダイレクトURIを使いません。
6. 発行された `….apps.googleusercontent.com` を、アプリの「初回設定」に入力します。PCとスマホでは同じクライアントIDを使用してください。コードで共通化する場合は `google-drive-sync.js` の `FP3_GOOGLE_CLIENT_ID` にこの公開IDを設定し、`npm run build` で配布HTMLも再生成します。IDは公開用であり、秘密鍵ではありません。
7. コードをmainへマージし、GitHub Pagesでmainのルートを公開します。公開後の `https://uchionsummer-alt.github.io/for_FP3/` を両端末で開きます。ローカルのHTMLファイルを直接開く方法ではGoogle接続を利用できません。

Google側の画面名は変更される場合があります。最終的な設定値はGoogleの管理画面で確認してください。

## 両端末で使い始める

1. **履歴のあるPCを先に接続**してください。最初に「バックアップ出力」も保存しておくと、移行前の状態を手元に残せます。
2. 「Googleドライブに接続」を押します。Googleライブラリを読み込む初回は、準備完了後にもう一度押します。これはSafariでもクリック操作から認証画面を開くためです。
3. Googleアカウントを選び、アプリ専用領域へのアクセスを許可します。初回のドライブが空なら、現在の学習履歴を送信します。
4. スマホも同じURL・同じクライアントID・同じGoogleアカウントで接続します。ドライブに履歴がある場合は、端末の旧履歴を復元用に保存したうえで、確認後にドライブの履歴を読み込みます。「接続前の履歴を保存」で旧端末履歴をJSONに書き出せます。

初回接続前に両端末で別々に蓄積した古い履歴の自動合算は行いません。同じ日の学習時間が同じ学習を表すか、別の学習を表すか判別できないためです。最初は引き継ぐ端末を決めてください。接続後の変更は、各操作の記録で自動統合します。

## 同期されるものと通信できないときの動作

- 読了・理解度・章別成績・復習・テスト履歴・日別学習時間・日程・目標・試験日・タイマーの開始/停止を同期します。
- 接続中は変更後約2秒と、画面が表示されている間の約30秒ごと、通信復帰・画面復帰時に送受信します。相手の端末への反映には通常数十秒かかります。
- オフラインの変更は端末に残り、認証が有効なら復帰後に送信します。未送信の状態でブラウザーの保存データを消すと、その端末だけにある変更は失われます。JSONバックアップも引き続き使えます。
- Googleのアクセストークンは短時間で期限切れになります。ブラウザーだけで動作するこの方式には長期のrefresh tokenを保存しません。期限切れ・ページの再読込・ブラウザー再起動後は、接続ボタンからの再認証が必要です。**常時ログインを維持する方式ではありません。** 再接続するまでは端末保存を続けます。
- タイマーは共有の1セッションです。一方で始めて、もう一方で停止できます。同じタイマーの終了を2端末で行っても、先に終了した1件を採用します。各端末で別のタイマーを同時に走らせる運用は避けてください。
- 同じ項目を両端末で変更した場合は版の新しい変更を採用します。端末の日時は自動設定にしてください。別単元の変更・別々の学習時間・テスト履歴は統合します。
- 「全データを初期化する」は、接続済みアカウントの同期履歴にも反映されます。確認画面を読み、先にバックアップを保存してください。初期化後は旧版のオフライン変更によって履歴を復活させません。

## 保存領域と権限

`appDataFolder` はこのGoogleアプリ専用の非表示領域で、通常のGoogleドライブの画面にはファイルが並びません。他のドライブの文書や写真は読みません。同期記録には学習データだけを含め、認証トークンはメモリー内だけに保持し、JSONバックアップやドライブへ保存しません。端末の接続記録にはアカウント識別子・表示用メールアドレスを保存します。

同期では変更を含む新しい版を保存し、成功を確認してから取り込んだ旧版だけを整理します。別端末が並行して作った未読の版は削除しません。Googleアカウントの権限撤回やドライブの容量不足時は、端末保存を続けて状態を表示します。接続解除ボタンは端末の同期を止めます。Google側のアクセス権そのものを取り消す場合はGoogleアカウントの接続管理を使ってください。
